# 批量补充交付记录（2026-11-01）

每个问题仍独立填写，底部统一提交已填写和明确勾选跳过的项目。一批最多4项，只创建一个任务和一个会话轮次；空白项目不提交，不解释为否定。跳过是本批次的待提交选择，勾选本身不发请求。取消勾选可以恢复原草稿并继续编辑。

后端沿用 /api/tasks/{id}/follow-up，以 action=batch 区分批量请求。问题原文由父轮次恢复，前端只发送 index、action、text。每条回答上限500字符，整个上下文仍上限3000字符。整批先校验，再在既有SQL事务中保存，不部分保存、不截断。即时规则检查所有回答的正文，触发时不等待模型。问题文字、跳过标记不加入可供模型逐字引用的用户事实原文。

历史记录的 contribution.items 保留本轮各个问题及对应答案。外层text仅供历史摘要显示；模型上下文使用items结构，不重复拼接摘要。原有单条回答、跳过及事实纠正接口仍可用，旧历史无需表迁移。

前端提交失败时恢复父轮的结果和问题，保留已填写内容和跳过选择；成功后清空旧草稿，显示新问题。未提交草稿只存在当前页面内存，不保存到localStorage或数据库；刷新或切换会话不会保留。本次没有添加新的锁、自动重试或异常捕获层，沿用原任务边界和既有规则。
